# 现在->必胜算法
我们在社交媒体上经常能看到有关五子棋的必胜阵法，虽说有很多不理会敌方“死活”的搞怪阵法，但还是有很多可取之处，将其可行典例取出并进行整合，就得到了我们的`现在->必胜算法`。这个方案基于以下考虑：  
***
## 阵法选择和匹配问题
1. **阵法如此之多，如何挑选？**  
 - 寻找网络上已被整合的“阵法宝典”，其中含黑棋阵法13个，白棋阵法8个  
2. **如何嵌入算法中，让匹配得以实现？**  
 - 将每个阵法单独拆分，作为数据库存储在`WinningPart.py`中   
 - 黑棋阵法：每个状态都保证数组中数字之和为`0`，故按`0黑0白`、`1黑1白`、`2黑2白`等情况对阵法及其下步落子进行存储   
 - 白棋阵法：每个状态都保证数组中数字之和为`1`，故按`1黑0白`、`2黑1白`、`3黑2白`等情况对阵法及其下步落子进行存储   
 - 因阵法中各方棋子数均不大于3，即不会出现真正的必胜局面，所以在`WinStrategy.py`中，优先遍历`WinningPart`匹配阵法  
***
## 技术实现方案
1. **算法架构**
```mermaid
graph TD;
    classDef process fill:#E5F6FF,stroke:#73A6FF,stroke-width:2px;
    classDef decision fill:#FFF6CC,stroke:#FFBC52,stroke-width:2px;
    classDef io fill:#FFEBEB,stroke:#E68994,stroke-width:2px;
    A[初始化WinStrategy<br>初始化棋盘 玩家 模式等]:::process --> B[加载棋盘数据<br>解析JSON数据更新棋盘状态]:::process;
    B --> C{是否匹配阵法}:::decision;
    C -->|是| D[根据阵法获取落子<br>返回匹配阵法的落子坐标及理由]:::process;
    C -->|否| E[扫描威胁点<br>检测对手和自身威胁点]:::process;
    E --> F{是否有高优先级对手威胁}:::decision;
    F -->|是| G[防御高优先级威胁<br>返回防御高优先级威胁的落子坐标及理由]:::process;
    F -->|否| H{是否有高优先级自身威胁}:::decision;
    H -->|是| I[发动高优先级进攻<br>返回发动高优先级进攻的落子坐标及理由]:::process;
    H -->|否| J{是否有可利用空位构建低级威胁}:::decision;
    J -->|是| K[构建低级威胁<br>返回构建低级威胁的落子坐标及理由]:::process;
    J -->|否| L{是否存在中心区域空位}:::decision;
    L -->|是| M[占据中心区域<br>返回占据中心区域的落子坐标及理由]:::process;
    L -->|否| N[随机找空位落子<br>返回随机落子的坐标及理由]:::process;
    D --> O[/返回落子坐标及理由/]:::io;
    G --> O;
    I --> O;
    K --> O;
    M --> O;
    N --> O;
   ```
2. **关键技术**：
   - 21种预定义必胜阵法（13种黑棋+8种白棋）,见`WinningPart`文件
   - 四向旋转和镜像对称匹配
   - 多级威胁检测机制，以上两点见`WinStrategy`文件
3. **入口对比**
   - `main.py`：主要用于静态输出。可以选择自己的棋子颜色（黑棋或白棋），并通过文件或直接粘贴 JSON 的方式输入棋盘信息。程序根据输入的棋盘信息，使用 WinStrategy 类生成落子决策，并将结果以 JSON 格式输出，同时还可以选择弹窗展示结果。整个过程是一次性的，不涉及与网页的交互，更像是一个离线的算法测试工具
   - `Web_main.py`：可以对接五子棋网页实现动态对弈。它通过 GomokuClient 类与前端 API 进行交互，实现了创建新游戏、查看当前棋盘、算法自动落子、自动对弈等功能。用户可以在交互界面中选择不同的操作，程序会根据用户的选择调用相应的 API 接口，获取棋盘信息、提交落子等，从而实现与网页的动态交互（默认对接项目成员所写的五子棋网页）

4. **数据结构**：
   - 使用9×9二维数组表示棋盘
   - JSON格式输入输出
   - 坐标转换系统（数组坐标↔数学坐标）

## 实际效果与优势
经过实际测试，该方案表现出：

1. **性能优势**：
   - 响应时间<100ms
   - 内存占用<10MB
   - 支持实时对战，由`GomokuClint.py`实现

2. **策略优势**：
   - 准确识别关键攻防点
   - 中盘胜率显著提升
   - 决策可解释性强

3. **扩展优势**：
   - 阵法库可动态扩展
   - 易于集成到现有系统
   - 支持多语言调用

## 经验总结
该方案特别适合：

1. 需要快速响应的对战场景
2. 中盘复杂局面的决策
3. 对算法可解释性要求高的场景
